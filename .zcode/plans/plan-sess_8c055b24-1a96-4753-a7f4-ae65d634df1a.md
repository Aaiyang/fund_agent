## 关键架构决策
1. **数据层双轨**：规范 7.1 要求 SQLAlchemy Async + asyncpg，而现有 `database_service` 是同步 psycopg 引擎。新增 `app/core/database.py`（`create_async_engine` + `async_sessionmaker`），新模块全部走异步引擎；现有 auth/chat 代码不动，共用同一 PostgreSQL。
2. **目录按规范 7.2 扩展**：新增 `repositories/`、`integrations/{fund_data,holdings}`、`analytics/`、`workers/`、`domain/{fund,watchlist,portfolio}`；复用现有 models/schemas/services/core 与模块级单例模式。
3. **缓存与锁**：复用现有 `cache_service`（Valkey/Redis + 内存兜底），新增 SET NX 分布式锁 `fund_sync:{fund_code}:{business_date}`；无 Redis 时降级为进程内锁。
4. **后台任务**：Taskiq + Redis broker（新增 taskiq/taskiq-redis 依赖）；Redis 不可用时截图识别降级为进程内有界 asyncio 任务（状态仍落 PostgreSQL），不阻塞流程。
5. **AKShare 阻塞隔离**：`asyncio.to_thread` + `Semaphore(AKSHARE_MAX_CONCURRENCY)` + tenacity 重试 + 超时；`AKSHARE_MAX_CONCURRENCY/TIMEOUT/MAX_RETRIES` 全部环境变量可调。
6. **截图识别**：`ScreenshotPositionExtractor` → `VisionAdapter`（默认 SiliconFlow OpenAI 兼容 Qwen-VL，`VISION_*` 配置可换）；提取→FundResolver→Normalizer→Validator 全链路带 confidence；无可用视觉模型时批次置 PARSE_FAILED。原图仅临时文件，确认/失败后删除，不入库。
7. **前端**：React Native + Expo（expo-router + TanStack Query + Zustand + SecureStore）替换 `frontend/`；旧 Vinext web 前端从回滚提交可找回。

## 数据模型（一次 Alembic 迁移，按规范第12章）
`funds`、`fund_nav`(唯一键 fund_code+nav_date)、`watchlists`、`watchlist_groups`、`watchlist_group_items`、`portfolio_accounts`、`portfolio_positions`(唯一键 account_id+fund_code，含 version/updated_at 乐观锁)、`transactions`、`holding_imports`、`holding_import_items`；新模型注册进 `alembic/env.py` 与 `models/database.py`；所有外部来源数据带 source/as_of/fetched_at。

## 后端工作包
- **WP1 基础设施**：core/database.py（asyncpg）、core/task_queue.py（Taskiq broker+worker 入口）、缓存锁、config 新增 AKSHARE_*/VISION_*/TASKIQ_*/IMPORT_* 配置与新路由限流键、迁移。
- **WP2 基金数据**：`FundDataProvider` Protocol → `AKShareFundProvider`（隔离/重试/限流）、Normalizer、FundRepository/FundService（搜索/详情/净值/历史）、AnalyticsService（区间收益/最大回撤/波动率，纯 Python 计算）、FundSyncWorker（Hot/Cold 策略 + 幂等键 + 分布式锁 + 有界并发）、API：`GET /funds/search|{code}|{code}/nav|{code}/performance|related-sectors(占位)`。
- **WP3 自选**：watchlist 增删查改 + 分组 CRUD + 分组内排序，列表返回 latest_nav/daily_return/is_held。
- **WP4 持仓**：accounts CRUD（含 last_imported_at）、positions summary/list/get/patch（乐观锁冲突返回 409）、transactions 查询 API（按 fund/account 过滤）。
- **WP5 持仓导入**：`HoldingImportProvider` Protocol + Manual/Screenshot 两实现；imports API：`POST /holding-imports/manual`（返回草稿待确认）、`POST /holding-imports/screenshots`（multipart 多图 → 202 + import_id，Worker 异步识别）、`GET /{import_id}`（轮询状态）、`PATCH /{import_id}/items/{item_id}`、`POST /{import_id}/confirm`（唯一写持仓入口，覆盖快照 + 写 IMPORT_ADJUSTMENT 审计 + 删临时图）、`DELETE`、`GET /history`；多图按标准代码去重、差异预览（当前→识别→导入后）、状态机 UPLOADED→PARSING→REVIEW_REQUIRED→CONFIRMED→APPLIED / PARSE_FAILED / CANCELLED。
- **WP6 Agent 占位与认证补充**：`POST /api/v1/agent/chat` → 501 not_implemented；`POST /auth/refresh`（Refresh Token）；现有 chat/LangGraph/Checkpointer/Langfuse 原样保留。
- **WP7 前端 Expo**：4 Tab（持有/自选/Agent占位/我的）+ fund/[code]（概览/业绩走势/我的持仓/加删自选/修改持仓入口）+ account/*（列表/新增/详情）+ position/edit + holding-import/*（入口/manual/screenshots/[importId] 确认页）+ transactions；登录/注册页；react-native-svg 净值折线图；SecureStore 存 Token；TS 类型对齐后端 Schema。
