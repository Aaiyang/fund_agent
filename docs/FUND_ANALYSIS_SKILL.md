# Fund analysis skill

Backend builtin fund-analysis v1.4.0, tools v14, prompt fund-agent-v20. Entry: backend/app/agent/skills/fund-analysis/SKILL.md; supporting evidence/protocol: references/evidence.md. Mobile assistant messages now render validated fund-chart blocks as interactive unit NAV charts, including restored history. Web integration is deferred. Portfolio-wide diagnosis now routes to portfolio-diagnosis; fund-analysis remains the full workflow for named-fund research or an explicitly requested deep dive.

Complete holdings/fund research routes to load_skill(skill_name="fund-analysis"), optionally section="evidence". Simple NAV lookups use existing tools directly. The report covers authenticated holdings; manager/performance potential and a one-year chart; evidence for recent moves; conditional short (1–3 months), medium (3–6 months), long (6+ months) responses; and policy impact conditions with provenance. Default portfolio depth is at most the top three positions with explicit scope, prioritizing named funds. Independent calls may be batched; code/ID dependencies remain sequential.

Only packaged allowlisted resources are read, once at module load. No arbitrary file, URL or script execution is supported. Trusted skill workflows remain subordinate to system rules; external news, holdings and memories remain data. Model selection and orchestration are not a mandatory five-stage state machine.

get_fund_analysis_data accepts only a six-digit public fund code. Existing async FundService supplies NAV for twelve calendar months through business today. Pure analytics compute unadjusted NAV changes, observed drawdowns, price-range position and, when at least 120 daily points pass quality guards, annualized NAV volatility. Ratios use 0.1 for 10%. Identical dates/values are deduplicated; conflicting dates, nonfinite/nonpositive and out-of-window records are excluded. Metrics precede weekly display sampling; unavailable evidence stays unknown.

get_positions exposes authenticated cost NAV and its derived flag. get_fund_holdings preserves available latest stock price/change/time. Snapshot performance is also computed from unadjusted NAV and now declares this basis. These values do not establish total return, manager alpha, precise contribution, market valuation percentile or future outcomes. NAV can decrease on distributions; see [Investor.gov's distribution explanation](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins/fund-distributions-investor-bulletin). Historical disclosure and today's prices cannot explain prior-month moves without matching evidence.

chart_code_block is now a fund-chart v2 reference with exactly schema_version=2, type=fund_performance and a six-digit fund_code. The tool still provides research metrics and coverage warnings, but sends no NAV series to the model. Models copy the tool block unchanged; no URLs, personal costs, identity or executable expressions are accepted.

Mobile FundAnalysisChart passes only the code to FundPerformanceCard, an Agent-only data adapter that renders the existing NavChart. The detail screen and NavChart are unchanged. Existing authenticated fund detail/NAV and index catalog/history APIs supply the values. Period and benchmark switches trigger ordinary queries, without LLM calls. The detail screen retains its personal cost line; Agent cards show public performance only. Closed valid legacy v1 blocks are recognized but their embedded values are ignored and replaced by backend queries. Cards display current query dates and actual coverage, so old replies do not constitute frozen chart snapshots. Unit NAV changes remain unadjusted for distributions. Empty/error/retry states are visible and shared query keys reuse the cache. Web integration is deferred.

tests/test_fund_analysis_skill.py checks allowlisting, no request file IO, private input exclusion, dates/numbers/extra executable fields, metrics before sampling, incomplete/stale/conflicting data, cost/quote fields, and repeated normal/streaming Agent graph paths with mocked LLM/holdings. This does not benchmark real-model adherence or prove causal attribution. Restart the backend; no migration or new dependency is needed.

## Mobile research cards

The public fund search page, GET /funds/search and the agent search_funds tool share FundService.search(). When substring search finds no rows, name queries use the same full-directory matcher as analysis selection and return the deduplicated similarity top three. Numeric queries remain code searches. Candidate codes are read or first registered without reapplying the original substring or replacing existing canonical names. Ordinary search still supplies NAV and live per-user flags; shared caches contain public rows only. Analysis selection reads identifiers without loading NAV.

Reports use a conclusion, performance chart, disclosed-stock tiles, factual metric tables and horizon-specific conditions. Charts fetch backend data by fund code for 1/3/6 months, 1/3 years or since inception, with real benchmark selection and no additional LLM call. Fewer than two dates produce a missing-data state. get_fund_holdings continues to emit a fund-holdings v1 JSON fence with at most ten public disclosed stocks, report period and weights in percentage points. Unknown, invalid or duplicate weights are omitted from the card while the research payload is preserved. The mobile card starts with six stocks and expands, with disclosure/provenance and non-real-time labels.

Implementation: mobile/components/MarkdownText.tsx, FundAnalysisChart.tsx, FundPerformanceCard.tsx, NavChart.tsx, FundHoldingsCard.tsx and shared/ contracts. Metro watches only the additional shared directory. Restart the backend for cached skill resources and Expo/Metro for its configuration. No database migration or dependency installation is needed. Peer-average curves, rankings, technical indicators and sector candlesticks still require additional verified data. Fund periods and real index benchmarks reuse the existing APIs.

Validation: npm test, typecheck and lint in mobile; backend fund-analysis and chart-contract tests. Fixtures are explicitly simulated test data, never returned as live fund data.


## Ambiguous fund names

For named-fund analysis, call resolve_fund_for_analysis(keyword) before dependent research tools. The independent fund_selection subgraph searches the existing service and deduplicates codes. A unique exact full name or an exact six-digit code resolves directly. Names use the complete directory and existing name matcher, with normalized labels, omitted-word matching and similarity ranking. Deduplicate codes before selecting the top three; even a single fuzzy candidate requires confirmation. Candidate resolution does not fetch NAV or private holdings. Share classes remain distinct. Empty results request clarification.

The choose node persists candidates before interrupting. Mobile displays the choices and recovers them through GET /chatbot/pending-action. POST /chatbot/fund-selection/decision validates the authenticated session, real interrupt ID and candidate membership. Selecting resumes the original question without searching again; cancelling stops without another LLM call. Other tools emitted in the same unresolved batch are deferred with paired ToolMessages. The tool entry still depends on model adherence to the system prompt/skill; ranking uses the deterministic name matcher rather than an unrestricted natural-language extractor or LLM-generated candidates. Restart the backend; no migration or dependency is needed.


## Research without personal positions

Any queryable fund can be researched by name or code, without holding or watchlisting it. Public research starts with fund overview and uses public fund tools directly. Personal portfolio tools are needed only when the user asks to incorporate their positions, costs or P/L. Empty positions do not end research; failed or skipped personal queries mean ownership is unknown. Public reports still include performance charts and conditional short-, medium- and long-term observations, without invented personal costs or returns.
