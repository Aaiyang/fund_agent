# 基金分析 skill

后端内置 `fund-analysis` v1.4.0，工具集v14、系统提示词fund-agent-v20。入口在 `backend/app/agent/skills/fund-analysis/SKILL.md`，工具证据与图表协议在其 `references/evidence.md`。移动端复用详情业绩组件，网页端留待后续接入。整个组合的诊断现在优先加载portfolio-diagnosis；指定基金研究或明确要求深入单只基金时仍使用fund-analysis。

## 基金名称有歧义时先选择

普通基金搜索页、`GET /funds/search` 和 Agent 的 `search_funds` 共用 `FundService.search()`。代码/名称子串搜索没有结果时，名称查询使用与分析选择节点相同的完整名册匹配规则，按相似度去重返回 Top3；纯数字查询保留代码搜索。候选按代码读取或首次登记主数据，不用原子串再次过滤，也不覆盖已有正式名称。普通搜索继续返回净值及当前用户的自选、持仓标记；共享缓存不保存个人标记。分析候选解析只查标识，不加载净值。

分析名称或简称时先单独调用 `resolve_fund_for_analysis(keyword)`，主图进入独立 `fund_selection` 子图：search 节点调用已有基金服务、按代码去重；完整名称唯一匹配或代码准确匹配时直接继续。名称候选通过已有 name_directory 的完整名册（登记名与展示简称）和 rank_names 匹配，支持省略名称中间词和混合/股票等展示标签；按相似度排序，先按代码去重，再取最多三个候选。单个模糊候选也等待用户确认，保留候选名称、代码和 A/C 份额。目录未提供类型时不编造；无相关候选才请用户补充，不拿无关基金凑满三条。解析候选阶段不抓取净值或个人持仓。普通列表查询仍用 search_funds。

choose 节点中断并保存候选，移动端展示选择卡片；刷新通过 GET /chatbot/pending-action 恢复。POST /chatbot/fund-selection/decision 仅接受当前会话的真实 interrupt_id 和候选代码，或取消，不接受客户端候选列表。选择后沿原问题继续，恢复不重复搜索；取消直接终止本次分析，不额外调用模型。同批次尚未确认对象的工具返回 FUND_SELECTION_PENDING，确认后再重新调用，保持 ToolCall/ToolMessage 配对。

节点入口由模型的工具选择触发，系统提示词与 skill 都要求名称分析先解析；这不等于强制识别任意自然语言中的所有基金名称。候选排序采用已有名称匹配器的确定性分数，不使用大模型生成代码或候选。无需迁移数据库或新增依赖，后端需重启加载新工具与提示词。

## 调用与五部分报告

用户说“分析我的基金持仓”“这只基金潜力怎么样、最近为何下跌、接下来怎么办”等完整研究需求时，系统提示词引导Agent先调用 `load_skill(skill_name="fund-analysis")`。初次研究可再加载 `section="evidence"`，而简单净值查询直接使用业务工具。

1. **持仓现状**：按认证用户读取组合与持仓，展示成本、成本净值、市值、盈亏、占比和日期；多账户分开，不虚构缺失字段。
2. **基金潜力**：基金类型、经理与任职稳定性、历史业绩和风险；加入真实近一年净值图。没有同类排名、基准和经理个人回报时不补造。
3. **最近为什么涨跌**：结合定义好的净值窗口、历史前十重仓、行业/板块和公开事件，区分数据、候选解释及证据缺口。今日行情不能解释过去一个月，季度披露不能当实时持仓。
4. **接下来怎么办**：结合成本、仓位、已确认目标和适用市场证据，分别给短期1–3个月、中期3–6个月、长期6个月以上的判断、行动条件、风险和复核信号，不自动交易。
5. **政策影响**：保留来源、发布时间、政策阶段、传导渠道和关联依据；方向为条件判断，事件工具的unknown不能改写为确定利好/利空。

全组合先检查总览，默认深查市值最大最多3只，说明没有展开的部分；用户点名优先。工具数量受图的循环预算约束，独立查询可在一轮并列调用，依赖真实代码或事件ID的步骤顺序执行。该流程由模型按需选择，不是保证五步完成的强制状态机。

## 后端能力

`load_skill`只读取打包在项目里的固定白名单，技能资源在模块加载时读入；请求中不读取任意文件、URL，也不执行脚本。skill内容从属于系统规则及本轮范围，其他工具、新闻、记忆和截图的文字仍是数据。修改skill后需重启或开发重载。

新增fund组工具 `get_fund_analysis_data(fund_code)`：通过既有异步基金服务取得业务今天向前12个日历月的日净值，清理非有限/非正/越界数据；相同日期相同值去重，同日冲突排除。派生计算在app/analytics，不用LLM算金融指标，不引入额外LLM调用。

返回未复权净值样本变化、1/3/6月净值变化、观察最大回撤、距离观察峰值的回撤、样本高低区间线性位置；达到120个日点且无明显质量问题才提供年化净值波动率。指标为比值，0.1表示10%。先计算再按周采样，不用周图算精确风险。区间位置不是估值分位；没有完整日历、复权、基准和历史指数工具时不宣称完整回报、牛熊阶段或精确收益归因。

现有get_positions新增average_cost_nav及其派生标记；get_fund_holdings保留已有price/change_pct/quote_time，无法核验日期时不能归因。snapshot业绩与风险同样来自单位净值计算，新增performance_basis说明未分红复权。

## fund-chart v2：按基金代码读取后端

get_fund_analysis_data只输入六位代码，不允许模型提交图表点、成本、身份、URL或任意日期。输出 `chart_code_block` 是完整的fund-chart栅栏和纯JSON，报告逐字嵌入；不执行HTML/JS/Python。单位净值未复权，并非含分红的总回报，详见[Investor.gov分配口径说明](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins/fund-distributions-investor-bulletin)。

JSON只包含schema_version=2、type=fund_performance、fund_code六位字符串。模型仍取得真实日点计算的研究指标、覆盖日期和缺口提示，但净值序列不再传给模型。客户端直接请求已有认证接口：基金详情、净值历史、指数目录与指数历史。

数据不足仍返回基金引用，由客户端显示加载、空状态或失败重试。研究指标仍保留窗口起点不覆盖、截断、超过14日缺口、旧净值与异常提示。起点覆盖以首点距请求起点不超过10自然日判断，只是边界容差，不能证明每天数据齐全；末点距业务今天超过7自然日标记stale，不根据自然日间隔推断交易所开市。

移动端FundAnalysisChart仅传基金代码给FundPerformanceCard。后者仅是Agent聊天的数据适配层，读取后端后直接调用已有NavChart；原基金详情页与NavChart保持原样。支持1月/3月/6月/1年/3年/成立以来与基准切换，直接读取后端、共享查询缓存，不增加LLM调用。只识别完整闭合且固定字段有效的块，拒绝额外points、URL、个人成本、身份和脚本。旧v1聊天仍兼容，但忽略嵌入序列、按代码查询后端。卡片显示实际区间与指标日期，历史聊天图表随查询更新，不能作为回答当时的数据快照。详情页原有成本线保持原样；Agent卡片默认不显示成本线。

## 验证与使用

tests/test_fund_analysis_skill.py覆盖技能白名单/无请求文件IO、输入隔离、无效数值/日期/脚本字段、采样与日点计算、缺数/滞后/冲突、成本和报价字段、普通/流式Agent图连续三轮调用。模拟模型验证连接，不证明真实模型一定遵循全部分析步骤；经理、政策及重仓归因的证据缺口必须在实际回答中保留。

重启后端后可以说：“分析我的基金持仓，按现状、潜力、近期涨跌原因、三个期限的应对和政策影响展开，带近一年走势图。”无数据库迁移或新依赖。

## 移动端分析卡片

报告采用关键结论、业绩图、重仓卡片、指标表格与分期限建议的形式。业绩图只由基金引用触发后端查询，不足两个日期显示缺数状态，不补边界点。get_fund_holdings仍返回fund-holdings v1纯JSON代码块，最多10条公共披露股票，权重为百分点；未知/异常/重复权重不进入卡片，原研究字段仍保留。移动端默认展示前6只，支持展开；注明披露期、非实时持仓和数据缺口。

移动端实现位于components/MarkdownText.tsx、FundAnalysisChart.tsx、FundPerformanceCard.tsx、NavChart.tsx及FundHoldingsCard.tsx，验证协议位于shared/；Metro仅额外监听shared目录。更新后需重启后端与Expo/Metro。无数据库迁移或新依赖。同类平均、排名、技术指标和板块K线不补造；真实指数基准与多区间净值直接复用已有接口。

验证：mobile运行npm test、npm run typecheck、npm run lint；后端运行tests/test_fund_analysis_skill.py和tests/test_fund_chart_contract.py。测试用fixture明确为模拟数据，不会作为业务行情返回。


## 未持仓基金的公开研究

指定名称或代码时在全部可查询基金中搜索和研究，无需先持仓、加自选或导入。公开研究直接查基金工具，第一部分为基金概况与研究范围，后续继续经理与业绩、涨跌原因、三期限条件方案及政策分析。只有用户要求结合本人持仓/成本/盈亏时才查个人账本。查不到本人持仓也继续公开研究，不虚构个人收益；未查或查询失败时个人持仓状态是未知。基金披露的前十大股票与用户持有的基金是不同概念。
