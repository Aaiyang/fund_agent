# 历任基金经理与基金公告工具

工具位于 `fund` 分组：`get_fund_managers` 和 `get_fund_announcements`，都按六位基金代码查询。工具集版本 `v9`、系统提示词 `fund-agent-v13`；重启后端加载，普通和流式 Agent 共用，无数据库迁移。

## 历任经理

参数：`fund_code` 必填；`limit` 默认50、上限100；`refresh=false` 默认允许一小时内成功缓存，true 强制在线更新。

- `periods` 保留来源页面的团队区间，包含经理姓名/ID、任职起止日、来源任职期间和现任标记。多人共同管理保留多人，不能把团队回报归到某个人；本工具不返回任职收益。
- `tenures` 按经理ID合并相邻或重叠任职区间。不同经理同名不合并；离任后再次任职单独列段。
- `end_date=null` 且 `is_current=true` 表示来源页面标记“至今”。字段 `fetched_at` 是 UTC 获取时间，保留缓存原获取时间；来源没有提供页面业务更新时间，不能用获取时间冒充更新时间。
- 两个列表各受 limit 限制，`total_periods`、`total_tenures` 和 `truncated` 说明完整性。归并使用来源完整区间后再限制输出，避免先截断导致任职时间被缩短。

原始页面如 [华夏成长经理页](https://fundf10.eastmoney.com/jjjl_000001.html)。解析只选择该基金的历任表，不混入页面中经理管理的其他基金。页面基金代码、表头、经理标识和日期结构无法核验时返回错误，不回退成现任姓名或空历史。

## 公告、报告和重大变更

参数：fund_code；category 默认all；可选 start_date/end_date（发布日期区间）、keyword（标题关键词）；page 默认1、上限1000；limit 默认20、上限50；refresh 默认false，允许5分钟内成功缓存。

| category | 范围 |
| --- | --- |
| all | 全部公告索引 |
| reports | 定期报告 |
| personnel | 人事调整 |
| dividend | 分红公告 |
| operation | 发行运作 |
| sales | 基金销售 |
| other | 其他公告 |
| major_changes | 全部公告当前页中的重大变更标题线索 |

结果包含标题、发布日期、来源分类、公告ID和原文链接。`content_available=false` 明确尚未获取正文或PDF，不能声称已经读过报告并据此生成财务结论。外层 `as_of` 是当前返回索引中最晚的可核验发布日期，单条日期仍保留；发布日期不等于事件生效日期。

“重大变更”由可解释的标题规则识别：经理变更、合同修订、清算、合并转型、投资范围/策略、基金名称/业绩基准、管理人/托管人、费率及申赎调整。`major_change_hints` 是待核验线索，不是官方完整分类、不表示变更已生效。销售机构业务终止不直接标为基金合同终止。

每次扫描所选来源类型的一页，固定最多50条，再做日期、关键词和重大变更筛选：

- `upstream_total` 是上游所选类型的总条数，不是筛选后的总数。
- `scanned_count` 是本页扫描量；`matched_count` 是本页匹配量。
- `invalid_items` 为已跳过的无效条目，`missing_items` 为来源声明该页应有但未返回的条数；部分页均不缓存。
- `has_more`/`next_page` 指下一扫描页；匹配量超过limit时先增大limit至50读取本页其余结果。
- 无匹配不能证明其他页没有公告或基金从未发生变更。工具不无界扫描所有历史，不静默跨页拼成“全部”。

接口参照 [AKShare 的公告实现](https://github.com/akfamily/akshare/blob/main/akshare/fund/fund_announcement_em.py)，直接异步请求同一公开来源并保留分页元数据。请求只包含基金代码、来源类型和页码，不发送用户画像或持仓。代码、页数和条数在工具与适配器边界校验；真实报告ID才可构造固定域名原文链接。

## 故障与验证

公开请求超时10秒，并发最多4，网络异常通过 tenacity 指数退避重试最多2次；解析错误、身份不匹配和异常分页不会伪装成成功空结果。失败不缓存；字段无效的部分公告页不缓存并警告，未知发布日期不补今天。缓存故障仍尝试在线请求。该能力没有持仓或交易写入。

`tests/test_fund_disclosures.py` 验证共同管理、连续任职、再任/同名经理、页面身份、公告分类/链接/日期、标题线索边界、分页范围、缓存隔离和失败处理，以及普通/流式 Agent 多轮查询。模型替身只验证执行路径，未评价真实模型对提示词的遵循率。

可向 Agent 提问：“查询000001历任经理和任职时间”“查询005827最新定期报告”“查看000001近期重大变更公告”。工具只能查询所提供公开来源覆盖的信息，不能保证全渠道完整性。
