# 摘要压缩 V2 实施说明

达到配置输入预算的 80% 且有足够旧轮次时，压缩未覆盖的旧原文。默认至少有四个未覆盖历史轮次才触发；当前用户轮次不参与，最近两个历史轮次保留原文。80% 是本地 token 估算，未知模型使用兼容 tokenizer，并非供应商精确计数。

## 独立段与来源

新段只包含本批原文，不再携带上一段摘要。覆盖数只记录本批轮数，例如首批三轮、次批两轮保存为 `[3, 2]`，水位线为第五轮末尾。版本独立递增，不能用于累计覆盖数。

每段保存半开区间 `source_start/source_end`、首尾用户消息 ID、每轮消息指纹和总体来源指纹。指纹包含原文、消息 ID、工具参数和结果；恢复时验证段连续、不重叠、计数匹配，再与 checkpoint 原文核对。来源变更或历史截短后，旧段不参与本次上下文。

## 输入、输出与失败

- 摘要输入完整发送用户、助手和工具内容以及调用参数，取消原来用户/助手 400 字、工具 120 字的静默截断。
- 每次选择摘要输入预算可容纳的连续完整轮次前缀。摘要输出上限为输入上下文预算的八分之一，限制在 64～2048 tokens；摘要输入为上下文预算减此输出额度。极小预算可能不足以容纳摘要提示词或一个完整轮次，此时不压缩。
- 生产摘要调用由图层注入，继承认证用户模型与 LangGraph/Langfuse 追踪上下文，使用 `max_tokens` 的一次性纯文本路径，不绑定业务工具，不改变聊天模型降级位置。
- 摘要模型带 `nostream` 标签，内部摘要不进入客户端消息流，追踪仍保留；该行为对照 [LangGraph 官方 streaming 文档](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/streaming.mdx) 并用真实图消息流测试验证。
- 空输出、超限输出、工具调用、拒绝元数据或因长度截断的结果均拒绝发布。摘要与合并失败不推进相应水位线或 Epoch；写入前确认摘要固定开销与当前轮仍能装入预算。
- 摘要输入装不下全部旧轮次时，剩余轮次继续属于未摘要原文。预算不足仅按原有窗口策略选择近期完整轮次，原始 checkpoint 不会因摘要而被删除。
- 合并只选最旧的配置比例（默认一半，至少两个且取偶数），逐对合并相邻段。所有合并成功后一次发布，来源区间和覆盖总数不变。合并仍存在语义压缩损失，需要真实模型质量评估。

## 持久化与清空

数据库为权威来源，每次准备重新读取状态及 `session.context_revision`。同一进程按会话串行准备；多 worker 用 `UPDATE ... WHERE context_revision = expected_revision RETURNING id` 比较并更新，LLM 调用期间不持有数据库事务。

先提交数据库，再更新进程内摘要缓存。数据库失败时继续使用旧段及预算内原文；读取失败时本次不压缩，下次会重试读取。CAS 冲突说明其他 worker 已更新、会话已清空或删除，本次准备中止并提示重试，不能用旧水位线继续调用模型。

清空聊天在同一事务中删除 checkpoint、清空当前摘要与旧摘要备份，并递增修订号。清空前启动的摘要不能通过旧修订号写回。提交后还递增本地失效代次，防止数据库提交与本地发布之间的清空竞争。准备完成前再检查修订号，防止读取旧缓存期间发生变化。

此机制保护摘要状态；已经发往供应商的请求无法撤回，其他 worker 正在执行的整个 LangGraph run/checkpoint 写入并没有因此获得分布式取消能力。

## 上下文与 KV Cache

80% 的触发估算和最终装配统一计入：系统消息、摘要及标题、历史/当前原文、工具调用参数、工具名称/调用 ID、工具 schema、动态时间和 AgentStatus。固定开销先预留，近期原文使用剩余预算。

独立旧段冻结，追加新段时保留此前稳定前缀；旧段合并低频重写。Epoch 指纹现在包含真实摘要载荷与 Epoch 序号。该指纹用于本地观测，并不控制供应商 KV Cache、缓存 TTL 或真实命中率；供应商是否缓存取决于其自身机制。当前系统提示词仍含用户与记忆内容，尚未拆为纯全局 L0 和会话 L1。

## 迁移与运行

新增 Alembic 迁移 `c9a4e2176b03`，基于 `f8d3b6a2c901`：

- 新增 `context_revision`，默认 0。
- 新增 `context_state_legacy` 并复制迁移前的摘要载荷，保留审计与恢复依据。
- V2 不读取 V1 的错误覆盖数，从原始 checkpoint 达到阈值时按需重建。
- 旧摘要备份保留到用户清空或删除会话。原文缺失的历史不能靠修改计数恢复语义。

开发数据库已迁移。其他环境先运行 `alembic upgrade head`，再重启全部后端 worker，使旧算法停止写入。用户之前的本地启动命令未启用 reload，需要退出后重新运行。

## 验证

401 项常规后端测试通过，两项可选 PostgreSQL 测试默认跳过；显式开发数据库测试两项通过，临时数据均回滚。Ruff、Pyright 和应用导入检查通过。

新增回归使用真实 `ConversationSummaryManager`，只替换模型 IO，覆盖连续多次压缩、重启、来源范围、合并比例/失败、完整消息尾部与工具参数、错误响应、读写失败、预算阈值、同进程串行、跨进程 CAS 与清空竞争。

未调用付费模型评估实际摘要质量或供应商 KV 命中；兼容 tokenizer 的误差和多代合并的信息损失仍需用真实会话评估。
