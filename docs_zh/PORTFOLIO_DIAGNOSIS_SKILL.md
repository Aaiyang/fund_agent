# 持仓诊断 skill

后端内置 `portfolio-diagnosis` v1.0.0，工具版本v14，系统提示词fund-agent-v20，技能目录版本v6。主文件是 `backend/app/agent/skills/portfolio-diagnosis/SKILL.md`，证据边界在 `references/evidence.md`。

## 接入

沿用 `load_skill(skill_name="portfolio-diagnosis")`，默认加载instructions，需要详细证据限制或卡片协议时再加载evidence。注册器只加载固定白名单文件，模块导入时读取；不接受任意路径、URL、脚本或用户身份。不同skill返回各自版本，fund-analysis仍为v1.4.0。

系统提示词将“诊断我的持仓”“分析整个组合”“组合是否合理”“重复买了吗”“持仓太集中”“如何调整”路由到此skill；指定基金潜力和涨跌研究仍使用fund-analysis，简单持仓查询直接使用业务工具。入口由模型工具选择触发，不是新增强制诊断子图。Langfuse沿用现有主图调用链。

## 诊断流程

1. 核验账户范围，同范围并列读取get_portfolio及get_positions(limit=50)，复用本轮有效结果。工具失败不当无持仓，列表截断、未知金额和日期错位明确说明。
2. 报告组合现状与数据质量，引用真实汇总、单行仓位、成本和盈亏；账本行数不冒充去重基金数，获取时间不当净值日期。
3. 检查大仓位、重复代码和披露中的底层股票重合线索；默认最多深入3只不同代码基金，公开查询跨账户复用，账户成本分开。
4. 分析真实收益口径、单基金风险和资金期限适配；未知现金、其他资产或用户偏好时不推断全资产配置。
5. 输出最多3个有依据的关注项和1–3个月、3–6个月、6个月以上的条件方案，明确复核指标。只读建议，不交易、不自动导入或修改持仓。

当前没有专用组合聚合、收益曲线、穿透和优化计算工具，因此不输出模型自行计算的Top3合计、HHI、组合回撤/波动、相关性、精确重合度、目标仓位或调仓金额。现有工具给出的单行仓位和单基金计算指标可以直接引用；这些缺口不应通过模型心算填补。

## 图表与验证

按需复制现有fund-chart v2和fund-holdings v1代码块，移动端继续复用现有卡片和后端数据接口，无新前端协议。单基金走势图不当组合曲线。无持仓仅报告当前未登记；无权限、失败、部分列表及缺失数据保留边界。

回归测试覆盖白名单与版本隔离、请求期间无文件读取、真实主图加载与认证工具链、账户范围、空持仓、读取失败和超过50行的截断。测试使用模拟模型与业务数据；提示词路由与诊断质量仍需真实模型评估。
