# 写入与执行安全

持仓写入共用异步数据库事务。交易规划、期初余额、确认导入与账本投影之前锁定账户行。
持仓编辑使用带版本条件的原子更新；公开编辑接口没有提供版本时仅允许创建新行。

`POST /api/v1/portfolio/positions/{fund_code}/trades` 必须提供 `idempotency_key`，
长度为 1–64 且不能全为空白。响应不确定时，重试沿用同一个键和参数；同键不同参数返回 409。
请求键与参数指纹经过散列后保存在首腿流水的现有引用字段，无需数据库迁移。
重放返回当前持仓，不重复记账。移动端在提交成功前为相同表单保留原键。
其他旧客户端需要先增加该字段，再升级后端。

缓存锁返回 `LockLease`，释放必须使用该次获取的凭证。聊天、人工决策、清空历史和删除会话
共用同一会话锁；执行期间清空或删除返回 409，不会直接取消运行。取得锁后重新检查会话是否存在。
多进程部署仍须配置共享 Valkey/Redis。

认证和会话命名共用异步引擎。AKShare 等待超时不会在底层线程仍执行时归还并发许可，
同步数据提供方仍须具有网络超时。Broker 日志不输出凭据，结构化日志统一隐藏敏感字段与 URL 用户信息。

设置 `FUND_TEST_POSTGRES=true` 后，在具有应用表结构的隔离 PostgreSQL 数据库运行
`tests/test_portfolio_write_postgres.py`，验证并发冲突、超额卖出、回滚、取消与幂等重放。
测试使用独立连接，创建唯一测试记录并在结束时清理。
