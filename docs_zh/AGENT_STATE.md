# 父子图任务状态

主图新增 `route_task` 与 `continue_research`，三个研究子图共用有界取证与报告流程。
完整结构、父图与子图状态契约见 [研究工作流](RESEARCH_WORKFLOWS.md)。

## 本轮基金目标

GraphState新增turn_id和fund_selection_result。流式和非流式入口通过同一个_new_turn_state构造本轮输入：新问题生成一次turn_id并清空旧选择结果，人工resume沿用已有状态。消息历史继续由add_messages管理，不因清理本轮目标而删除历史。

基金选择子图通过FundSelectionResult回传turn_id、tool_call_id、status、keyword、真实基金和confirmed_by_user；resolved必须包含基金，not_found/cancelled不得保留目标。父图只使用匹配本轮标识的结果，取消或无匹配直接结束，解析成功的代码和份额作为动态研究背景供模型继续使用。不同研究对象仍需要各自证据。

工具消息继续与原始调用配对并保留，程序路由优先结构化状态。升级前没有结构化结果的旧检查点保留工具正文回退，损坏JSON不会使路由崩溃。FundSelectionCall将原始工具调用字典转成明确类型，保留原有节点名、私有候选和检查点命名空间。

## 持仓导入账户与恢复

导入先判断本轮用户需求，再检查附件。主图普通模型调用在用户明确要求图片导入时提出start_holding_import，route_attachments读取服务端本轮holding_import_ids：缺图提示上传，有图才进入子图。单有附件不启动导入；意图工具不接受模型填写批次、账户或持仓参数。历史UPLOADED批次不能通过旧复核工具在没有本轮附件时启动识别；已识别或处理中的草稿仍可查询和复核。缺图及OCR内容失败会返回配对工具结果和明确提示。

holding_account_id和holding_instruction保留为父图传入的初始要求。人工选定账户写入子图私有resolved_account_id及resolved_import_id，只适用于对应批次；每个调用完成即清理私有确认值。用户一开始明确指定的账户仍可以用于本轮多个批次，未指定时各批次独立询问。子图结束清理父图的本轮批次、账户和指令字段。

decision使用三个明确类型：识别继续、账户选择、人工决策回执。无效回复按未决策处理，旧字典检查点可转换成相应类型。账户ID拒绝布尔值、字符串和非正数；识别继续与账户选择核验import_id和当前阶段，其他批次回复不能推进流程。识别阶段允许真实取消回执继续读取数据库终态。

正式持仓写入仍由人工HTTP接口完成。图恢复后读取数据库核验终态，不以客户端或图里的“确认”直接写入。数据库草稿和持仓是业务事实来源，检查点负责流程暂停和恢复。

## 验证与范围

回归包含本轮结果注入、取消后新问题、损坏工具正文、跨批次恢复、账户类型错误、两个批次不同账户以及旧基金选择和旧工具节点检查点恢复。Langfuse、技能入口和客户端协议沿用现有调用链。会话整体并发协调不属于这批state修改，仍需单独统一普通聊天、流式聊天和人工决策的执行控制。
