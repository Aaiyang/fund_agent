# mem0 增量写入与可治理语义记忆

后端迁移 `e72a6d8f9103`，提示词 `fund-agent-v13`。继续使用已锁定的 mem0 1.0 + pgvector；结构化画像仍按 `USER_PERSONA.md` 走人工确认，不引入第二套记忆框架。管理前端尚未接入。

## 职责和范围

`memory_fact` 是内容、来源、版本、有效期和删除状态的权威来源。mem0 提供模型配置、embedding 和 pgvector 检索，向量只是可重建的索引。`memory_account` 管理开关、代际、版本和顺序；`memory_write_job` 是逐消息工作账本。

仅自动提取用户明确声明的研究偏好、过去分析事件。每条消息最多5条事实，正文不超过240字；正文和证据都须逐字来自当前真实用户消息。普通问答、寒暄、助手/工具/图片内容不写入；涉及敏感信息、假设、实际资产数值、权限指令的整条消息保守跳过。风险偏好、投资目标等结构化画像字段不维护第二份。

提取输入仅含当前新增消息、业务日期、最近30条有效记忆，不接收整段聊天。新历史事件的键由来源消息哈希隔离，不覆盖其他事件。原文检查不能证明语义理解正确：复杂否定、多意图及同义主题仍可能遗漏或误提取，需要用户纠错及领域样本评估。保守策略会跳过部分合理陈述。

## 增量与可靠写入

HumanMessage 在 chat 节点调用模型之前登记，流式和普通响应共用同一路径；工具循环不重复登记历史。用户/会话/消息 ID 哈希作为唯一键：重复运行同消息复用任务，同文新消息可单独处理。聊天失败或工具人工中断时，已登记任务仍保留。

先提交账本，再投递仅携带用户 ID 的 Taskiq 任务。入队失败保留 PENDING，独立恢复循环默认每15秒恢复待办和过期租约，不依赖热门基金同步开关。数据库登记默认3秒超时，失败不能承诺已记住，聊天可继续。

worker 使用 PostgreSQL 事务级咨询锁跨进程按用户互斥；领取/更新是短事务，外部模型调用不持有用户行锁。任务按序号执行，tenacity 指数退避，一轮最多3次尝试，尝试计数在模型调用前落库，崩溃也计入预算。默认每次90秒、租约330秒。失败保留 FAILED 供人工重试；显式重试开启新一轮有限预算，保留原顺序。

先存提取结果和事实，再更新索引；索引重试复用提取结果，固定向量 ID 防止确认丢失后生成重复向量。版本比较阻止旧索引确认改变新版本，旧任务不能覆盖同条目上较新的纠错/删除。成功、无事实或取消任务清除输入正文及提取载荷；失败输入保留到成功重试或清空/关闭取消，当前没有自动保留期清理。

关闭停止新写入和召回，取消旧代际提取任务，保留已有事实供管理；关闭期间仅清理待删除向量，不对保留正文发起新的 embedding 请求；开启后重建当前索引。清空立即抹除应用事实正文、证据和任务输入，推进代际并取消旧任务；保留消息哈希墓碑，重放不能复活。向量删除异步执行，失败可从 SYNC 任务重试，删除完成前也被数据库校验阻止召回。清除不删除持仓、画像、聊天检查点、既有外部日志/备份，也不能撤回已发出的模型请求。

## 按需召回与上下文

寒暄、纯日历、纯实时净值/行情查询跳过召回。分析、比较和记忆查询按当前问题检索：最多20候选，默认6条、1000个 cl100k_base 估算 token；动态尾部总预算仍由上下文管理器约束。默认6秒超时，失败返回空且不缓存，下次可恢复。

当前 pgvector 的 score 是余弦距离，越小越相关，使用 `distance <= 0.55`，不用 mem0 方向相反的通用 threshold。rerank 关闭，不调用额外重排模型。阈值需要按实际 embedding 和基金样本校准。

先过滤用户、managed_by 和代际，再读取数据库核对 ACTIVE/READY、条目版本和有效期。回答只用数据库当前正文，不用滞后向量文本。只缓存成功非空结果，键含用户/代际/版本/查询，缓存命中仍核对有效期。检索期间版本变化则丢弃结果。分析事件默认180天后不召回，研究偏好持续保留至修改/删除。

每轮刷新，工具返回后也刷新，覆盖普通、流式和人工中断恢复。记忆进入动态尾部，Agent 的 L1 memory_snapshot 留空，避免查询变化污染稳定系统前缀；历史记忆不补成已确认画像或工具授权。

## 管理 API

前缀 `/api/v1/agent/memories`，身份从认证取得，不接受用户 ID 覆盖。全部路由使用既有 Agent 限流；仅返回当前用户内容，任务列表不返回聊天正文或供应商错误详情。

| 方法/路径 | 用途 | 请求体 |
| --- | --- | --- |
| GET 空路径 | 最多100条未删除、未过期事实与来源 | — |
| GET `/settings` | enabled、revision、generation、globally_enabled | — |
| PATCH `/settings` | 开关 | `{"expected_revision":0,"enabled":false}` |
| PATCH `/{id}` | 直接纠错，成功204 | `{"expected_version":1,"content":"比较基金时优先看费用"}` |
| DELETE `/{id}` | 单条删除，成功204 | `{"expected_version":1}` |
| DELETE 空路径 | 清空应用语义记忆 | `{"expected_revision":0}` |
| GET `/jobs` | 最近任务状态，limit 1–100 | — |
| POST `/jobs/{id}/retry` | 人工重试失败任务 | — |

过期版本409，其他用户/不存在条目404，范围或字段无效422，数据库故障503。纠错直接用用户提交内容，不让模型再解释。修改后重新读取条目/settings，索引完成也可能推进 revision。

## 兼容、部署与观测

旧 mem0 条目没有可靠来源和版本，因此不自动纳入新召回，也不直接删除。仅 managed_by=fund_agent_memory_v2 且数据库存在当前版本的条目参与召回。旧集合及旧 SQLite 历史需另行审核迁移/清理，清空不声称清除了这些旧数据。新写入绕开 mem0 原生历史写入，避免新删除内容留在 SQLite。当前 SDK 的 AsyncMemory.search 在过滤时调用缺失方法，因此检索也通过适配层组合其 embedding 与 pgvector 原生接口，保持用户/代际过滤；服务关闭显式释放主索引、辅助索引和客户端。升级 SDK 必须复跑适配契约测试。

执行 `cd backend`、`alembic upgrade head` 并重启 API；Redis 部署也要重启包含 app.workers.memory_write 的 Taskiq worker（Makefile 已更新）。无 Redis 时进程内任务可运行，重启后由 PostgreSQL 账本恢复；生产建议 Redis + 独立 worker。

`.env.example` 包含登记3秒、召回6秒、写入90秒、提取输出最多8192 token、最大距离0.55、top-k 6、召回1000 token、输入8000字、事件180天、恢复15秒。提取输出预算独立于聊天上限，避免多条事实 JSON 被截断。索引 SQL 设置2秒执行、1秒锁等待、5秒连接超时；已发出的索引写即使协程取消也会等待结束再释放 worker 锁，避免后台旧写覆盖新版本。平台 LONG_TERM_MEMORY_ENABLED=false 停止自动召回和 worker；管理接口仍可清除数据库内容，物理向量清理待重新开启。

提取使用平台记忆模型，不继承当前聊天用户的模型凭据。Langfuse generation 关闭输入/输出采集，模型/验证失败只留错误类别；Prometheus 提供 memory_jobs_total、memory_retrieval_total、memory_retrieval_seconds、memory_write_seconds、memory_candidates_rejected_total，不以原文或用户 ID 作标签。可从 API 查看积压/失败，专门告警和自动保留期清理尚未配置。

测试覆盖范围、认证、距离方向、预算、失败不缓存、幂等向量与动态召回；FUND_TEST_POSTGRES=true 运行 tests/test_semantic_memory_postgres.py，验证真实数据库隔离、纠错、清除、租约、重试、咨询锁及原生 pgvector 插入/更新/距离检索/删除，临时向量删除、事务数据回滚。外部 LLM/embedding 使用替身，实际供应商质量需以真实样本持续评估。
